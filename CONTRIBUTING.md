# Contributing

Thanks for helping. A few rules keep this tool trustworthy.

## Language

Everything on GitHub (code, comments, commit messages, issues, PRs, reviews)
is in **English**.

## Pull requests

- CI must pass: typecheck, lint, tests (including the secret canary and the
  read-only allowlist tests), build, and offline smoke tests of the built CLI
  on Node 22 and 24. Run `npm run check` and the canary command below before
  pushing.
- A pull request needs one approving review before it is merged.
- Open it as a draft while you are still working on it, and mark it ready for
  review when it is done.
- If it touches authentication, the `safeFetch` allowlist or secret handling,
  say so in the description so it gets a closer look.

CodeQL is opt-in. It runs once the repository variable `ENABLE_CODEQL` is set
to `true`, which is planned for when the repository is public.

Maintainers: make the `CI` jobs required status checks on `main`, together
with one required approving review.

## Commits and versions

- [Conventional Commits](https://www.conventionalcommits.org/): `feat(github): ...`,
  `fix(net): ...`, `docs: ...`, `test: ...`, `ci: ...`, `chore: ...`.
- [Semantic Versioning](https://semver.org/). Add user-visible changes to the
  `Unreleased` section of [CHANGELOG.md](CHANGELOG.md).

## Releasing

The package is private and is **not** published to npm. Releases are GitHub
tags and GitHub Releases only. Install by cloning a tag, then
`npm ci && npm install -g .` (or `node dist/cli.js`). Global install from a
git URL (`npm install -g github:…`) fails prepare today; a project-local
`npm install github:…` works. `npm install -g .` symlinks to the clone.

1. In a pull request, set `version` in `package.json` and `src/version.ts`, run
   `npm install` to update the lockfile, and move the `Unreleased` entries to a
   new `## [x.y.z] - YYYY-MM-DD` section in the changelog.
2. After it is merged, tag the merge commit and push the tag:
   `git tag vX.Y.Z && git push origin vX.Y.Z`.
3. The release workflow checks that the tag is on `main`, matches
   `package.json`, and that both `CI` jobs (`typecheck, lint, test, build
   (Node 22)` and `(Node 24)`) succeeded on the tagged commit. If you rename
   those jobs, update `.github/scripts/require-ci.sh`. It then creates the
   GitHub release from the changelog entry.

## Local checks

```sh
npm ci
npm run check   # typecheck + lint + test + build
npm run fixtures   # writes the fake-credential fixtures to .fixtures/
node dist/cli.js --dir .fixtures/canary --offline --no-color | grep CANARY   # must print nothing
```

## Adding a connector

1. Copy `src/connectors/example.ts` to `src/connectors/<id>.ts`.
2. Fill in the `Connector` interface (`src/connectors/types.ts`):
   - `allowlist`: every request the connector may make, as exact
     method + host + path. Prefer `GET`. GraphQL queries must be declared with
     `graphqlDoc()` as constants. Each new rule is reviewed in the PR.
   - `detect(env)`: pure, no I/O. Use `detectSecrets()` and bind each secret
     to the provider's API hosts with `allowedHosts`.
   - `check(secret, ctx)`: use only `ctx.fetch`. Respect `ctx.offline`.
     Use `discardBody: true` when you only need the status code and the body
     may contain personal data.
3. Be honest about confidence: a `403` on a read probe does not prove the key
   cannot write. When in doubt, report `unknown`.
4. Never put secret values in findings. Use `secret.hint()` if you need to
   refer to a credential.
5. Export it as `export const connector: Connector`, with an `id` equal to the
   file name. The registry is generated by `scripts/gen-connectors.mjs`, so you
   do not edit any shared file.
6. Add `test/connectors/<id>.test.ts` with mocked responses (no real network
   in tests), and add a fake canary credential to the canary fixture in
   `scripts/make-fixture.mjs` (fixtures with real key formats are generated,
   never committed).
7. Document any trace the check leaves on the provider side (audit logs,
   request logs) in the connector's header comment and in the README.

## Security

See [SECURITY.md](SECURITY.md). Never paste real credentials in issues, PRs or
fixtures.
